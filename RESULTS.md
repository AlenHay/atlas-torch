## Noise floor: compiler variants (decision, M0)

* Variants: gfortran -O0/-O3, ifx -O0/-O2/-O3/`-fp-model precise`, all with the stock SAVE/zero-init semantics,
  built by `scripts/build_fortran.sh`.
* **DFSYNTHE/KAPPA9 have only ifx variants.** xnfdf/dfsynthe/dfsortp/kappa9 are written in Intel/DEC dialect
  (`OPEN(TYPE=..., READONLY, SHARED)`, `RECORDTYPE/BLOCKSIZE`, `TYPE*` output, rank-mismatched EQUIVALENCE,
  tab-format lines longer than 72 columns) and `RECL` for direct access is in 4-byte words under ifx but bytes
  under gfortran: a gfortran build would differ in I/O semantics, not floating-point noise. Their spread is
  therefore measured across ifx optimisation levels and fp models only (`tools/gf_shim.py` exists for
  best-effort gfortran builds; not used for tolerances). `rmolecasc` (Hollerith assignment ifx rejects) is
  built with gfortran -O3 in the ifx variants; it only reformats line lists.
* SYNTHE-family sources use direct-access files with RECL in bytes (gfortran convention): the ifx variants
  of that family are built with `-assume byterecl` (I/O units only; first attempt crashed in rh2ofast).
* ATLAS9 stock = gfortran -O0, so the gf-O0 variant is identical to stock by construction; the spread comes
  from gf-O3 and the ifx builds.
* Stages are scored stage-isolated: variant ATLAS9 runs use the stock ODFs, variant SYNTHE runs the stock solar
  model, KAPPA9-alone stages (`kappa9/<mix>`) the stock ODF.
* Tolerance rule (frozen once in `results/tolerances.json` by `tools/score/noise_floor.py --write`, before any
  torch result exists): `tol = max(3 x max-over-variants error vs stock, 1 quantum of the output format)`.
  The quantum (1 ulp for binary float64, last printed digit for text tables, 1 step for integer ODF/kapk
  tables) only matters when every variant agrees exactly. This session created this rule.

### DFSYNTHE and flush-to-zero (decision, M0, made before any full torch ODF existed)

* Stock DFSYNTHE/KAPPA9 is ifx with the default `-fp-model fast`, which runs with flush-to-zero/denormals-are-zero
  (FTZ/DAZ) and Intel's SVML. ifx `-O0` and `-fp-model precise` builds do not flush.
* Measured on the solar mix: ifx-O3 vs stock differs by at most 1 ODF step (1-2 entries out of 5.6 M), but
  ifx-O0 and ifx-precise differ by up to **3590 steps (3.6 dex)** in 0.35 % of entries, concentrated at cool
  temperatures (index 0-17, < 4400 K), low pressures and some frequency intervals — whole ODF rows shifted by
  ~3.3 dex, i.e. molecular opacity switched on/off, not rounding; kappa.ros differs by 0.005 dex.
* FTZ is real in xnfdf (vs stock, 13 586 `xnfpdf.dat` values are 0 in stock but nonzero at -O0; an
  `ifx -O0 -ftz` build removes that category), so the DFSYNTHE/KAPPA9 noise variants are run in stock's FTZ
  environment: `ifx-O3` (FTZ by default), `ifx-precise-ftz`, `ifx-O0-ftz`. **But FTZ is not the cause of the
  ODF jumps** (correction of an earlier note): `ifx-precise-ftz` still differs from stock by up to 3300-3590
  steps in ~0.3 % of entries, while its xnfdf output differs from stock only at rounding level. The jumps
  originate inside dfsynthe under `-fp-model fast` (root cause under investigation). Even at T >= 4571 K the
  precise builds reach 119 (solar) / 358 (alpha) steps somewhere: cool-and-warm ODFs are genuinely not
  reproducible across the Fortran's own compiler settings at the level of single entries.
* Consequence for gating (decided before any full-table torch ODF exists): the literal max-abs gate stays
  (3 x spread, i.e. ~±10 dex — recorded, but it gates almost nothing), and distributional metrics under the
  same 3 x rule carry the weight: `share_gt1` (fraction of entries off by > 1 step; Fortran spread ~0.3 %),
  `p999` (99.9th percentile |diff|; spread 24 steps), max-abs over T >= 4571 K, and kappa.ros max-abs.
  This session created both these metrics and the gate.
* Seen before freezing: the DFSYNTHE port agent reported one temperature (5012 K): port vs stock max 18 steps,
  vs ifx-precise 1 step (the port reproduces the non-FTZ precise build). No full-table torch ODF exists yet.

### Findings so far

* Correction (line readers, commit 44c6701): the claim "byte-identical except TABLOG fields" was wrong — the
  rmolecasc/rgfalllines ports did REAL*4 arithmetic in float64 (up to 79 ulp in ~600k records; the stage test hid
  it behind a 5e-4 helper tolerance). Fixed: all line programs now byte-identical to stock on the four reference
  windows (incl. TABLOG via libmvec powf, which only rh2ofast uses), and the test requires exact equality.
* Host vs container: the host glibc 2.43 `log10f` differs from the container's 2.39; all references and scores
  are produced inside the container.

* KAPPA9 alone: all four ifx variants reproduce the stock `kapk*.dat` and `kappa.ros` byte-for-byte (solar and
  alpha), so the KAPPA9 gate is one print quantum (1 milli-dex step / 0.001 dex).
* SYNTHE `spectrv`: a gfortran -O0 debug build reproduces the -O3 stock `spectrum.bin` bit-for-bit (10 nm window).
* Our solar ODF vs the one shipped in BasicATLAS `data/solar_ODF`: 0.6 % of ODF steps differ (up to 3.6 dex in
  rare bins), `kappa.ros` within 0.001 dex — the shipped tables come from other line-list versions;
  information only, the gate is our pinned build.

**Derived example stages** (`api/<example>/{structure,spectrum,odf}`): the examples run setups outside the

same kind (structures: all ATLAS9 models; spectra: all SYNTHE windows; ODF: both mixes). This is an extrapolation of
the measured noise floor, decided before any example ran with the torch backend. This session created these rules.
